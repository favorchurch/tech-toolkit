# Delivery roadmap and validation backlog

**Status:** starter toolkit published; adoption and certification are not yet demonstrated.

## V0.1 — Authored framework

- [x] Lock operating model, open-source policy, readiness stages, and distributed ownership.
- [x] Publish master charter, governance, security, and the ten-category index.
- [x] Draft portable Internet, Website, and App Development playbooks.
- [x] Provide launch, training, and reusable templates.
- [x] Establish lightweight automated public-document checks.

## V0.2 — Functional-lead validation

- [ ] Internet Lead walks through standard setup, monitoring, packdown, safe fallbacks and shift changes.
- [ ] Website Lead validates request intake, accessibility, design/brand approval, CMS staging and rollback.
- [ ] Engineering Lead validates issue/spec, review, CI, release, incident, and data-permission controls.
- [ ] Functional owners label procedures Verified, Provisional, or Proposed with dated evidence.
- [ ] Confirm the training pathway and ownership model for campuses without an on-site developer.

## V0.3 — Source and security hardening

- [ ] Review legacy public playbooks (including Git history, diagrams, archived slides) for actual secrets and sensitive topology **without publishing findings in public issues**.
- [ ] Verify old training decks and shared documents have appropriate access and sanitized links.
- [ ] Clarify source of truth for website requests, central/venue ownership and vendor subscriptions.
- [ ] Confirm procedures for emergency communications and off-hours escalation.
- [ ] Establish private addendum storage and approved credential vault references.

## V1.0 — Campus replication pilot

- [ ] Run a real site survey with evidence and an approved equipment list.
- [ ] Conduct Prepare and Assisted Launch for one pilot campus or venue.
- [ ] Observe a degraded-connectivity/stream recovery rehearsal.
- [ ] Demonstrate website content publishing under the approved local permission model.
- [ ] Demonstrate request/bug escalation and secure app support.
- [ ] Run certification acceptance tests; record independent sign-off, remediation and reassessment dates.

## Ongoing

A quarterly review, plus updates after meaningful incidents, releases, onboarding changes, or campus launches. Do not auto-mark roadmap items complete just because this Markdown file exists.
