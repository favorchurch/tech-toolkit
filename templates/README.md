# Templates, forms and reusable evidence

These are **blank public templates**. Completed forms that identify people, live infrastructure, real incidents or campus configurations must be kept in an approved restricted workspace. Never attach such completed forms directly to a public GitHub issue or PR.

| Template | Used for | Recommended owner |
| --- | --- | --- |
| [Project brief](PROJECT-BRIEF.md) | Product, app or cross-team work intake | Ministry requester / Product owner |
| [Website request](WEBSITE-REQUEST.md) | Quick updates, pages, events, ticketing | Requester and Website Lead |
| [Change request](CHANGE-REQUEST.md) | Controlled infrastructure, code or procedural change | System / Functional owner |
| [Incident report](INCIDENT-REPORT.md) | Impact, mitigation, root-cause evidence and prevention | On-duty incident owner |
| [Service log](SERVICE-LOG.md) | Internet setup, streaming, handover and packdown | Internet Captain |
| [Campus readiness](CAMPUS-READINESS.md) | Prepare, assisted and certification evidence | Campus Tech Lead / Central certifier |
| [Access review](ACCESS-REVIEW.md) | Least-privilege onboarding/offboarding audit | System / Security owner |
| [Team handover](TEAM-HANDOVER.md) | Role or responsibility transition | Outgoing and incoming leads |
| [Document review](DOCUMENT-REVIEW.md) | Dated validation and owner sign-off | Functional Lead |
| [Asset inventory CSV](ASSET-INVENTORY.csv) | Blank equipment register columns | Campus asset custodian |
| [Role competency CSV](ROLE-COMPETENCY.csv) | Blank skill demonstration evidence | Trainer / Functional Lead |
| [Budget planning CSV](LAUNCH-BUDGET.csv) | Category-based cost planning | Tech / Finance owners |

## Use and retention

1. Copy the applicable template to approved campus/team storage.
2. Fill the **role and status** fields, not real credentials.
3. Store sensitive evidence as restricted references, not embedded in a public document.
4. Obtain the required actual approval.
5. Link the sanitized outcome/status from the relevant tracker.
6. Retain or dispose of the completed record under organization policy.

The templates are a starting standard; do not treat sample status labels as proof that an approval happened.
